IMS 0.7.0 COMPOSITIONAL RETRIEVAL PATCH MANIFEST
=================================================
Base: IMS 0.6.2
Target: IMS 0.7.0

PURPOSE
-------
Generalized Q&A architecture upgrade for multi-term, multi-entity, multi-attribute,
comparison, relationship, false-premise, conditional, multi-hop, conflict, temporal,
calculation, indirect, typo-tolerant and multilingual questions.

This patch does NOT encode expected answers, locations, acronym expansions, line mappings,
compensation rules, or other corpus-specific facts. Regression examples appear only in
tests/evaluation material. Domain facts continue to come from accessible indexed documents.

CORE BEHAVIOR
-------------
- Build atomic evidence goals before retrieval.
- Optionally use a fast semantic planner for structurally rich/indirect wording.
- Preserve literal identifiers, numbers, negation, exceptions, conditions and user clauses.
- Search required goals independently instead of requiring all terms to co-occur.
- Search configured overview documents once per atomic goal in compositional mode.
- Reserve bounded candidate/evidence capacity per required goal before global reranking.
- Audit goal satisfaction using only evidence attributed to that goal.
- Perform one bounded targeted recovery pass for missing/partial goals.
- Give recovered evidence first admission to the bounded merged context.
- Require actual evidence for relationships/causation/override/applicability/entitlement.
- Treat user premises and confirmation wording as claims to verify.
- Detect conflict/precedence wording before legacy entity/facet shortcuts.
- Preserve Unicode word boundaries and allow multilingual semantic planning.
- Fail semantic-planner errors toward Research/verification rather than confident Direct.
- Never infer corpus-wide negative inventory from ordinary top-k absence.
- Persist goal plan/satisfaction/recovery diagnostics and bounded Prometheus metrics.

DATABASE / CORPUS
-----------------
No database migration.
No PDF reprocessing.
No OCR rerun.
No re-chunking.
No re-embedding.
No model-cache reset.

VM REBUILD
----------
Rebuild/recreate only api-1 and api-2, then restart nginx.
Do not rebuild inference-query, inference-ingest, worker, report-worker, postgres, valkey,
or model-bootstrap for this patch.
